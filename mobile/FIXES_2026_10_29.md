# Flutter safety fixes — 29 October 2026

These changes are in the working Flutter source. The previously released 3.0.0 APK/source ZIP are historical artifacts and were not rebuilt or replaced by this fix task.

1. Restore now holds the same exclusive lock as command saves through decryption, validation and durable commit. A save before restore blocks replacement if pending; a save during restore appends afterwards. Authentication is checked again before committing an imported backup.
2. Return uses the shared whole-bag input field, which rejects a fractional paste as a whole edit, checks integer values even if a controller bypasses input formatting, and enforces the remaining-quantity limit.
3. Customer/record text changes rebuild the Back guard. Invoice text, item, account and discount changes update the same guard. Return has a guard too. Cancel keeps the editor; Confirm permits navigation only after the guard has rebuilt.
4. Lock persists an account-specific secure-storage marker before hiding records. Startup never restores a valid session while this marker is set. Successful password sign-in/unlock clears it.
5. All private API requests/downloads share a 401 boundary. It hides private records immediately and persists the locked state. The application Navigator is replaced when access changes, disposing open editors/dialogs and their Back history. A malformed 401 body is still treated as authentication failure; a late response for an old cookie cannot expire its replacement session. Pending financial operations remain durable.
6. PDF business headings are measured within the text column beside the logo. Phone position and invoice body start are derived from actual text height. Long English/Bengali names wrap within the page and do not overlap the phone number.

Validation: Flutter 3.47.8 / Dart 3.13.7; analyzer: no issues; all 74 automated tests pass. Tests include gated restore/save interleavings, persistent lock/restart, customer/invoice text-only Back confirmation, fractional Return paste/controller values, open-editor/dialog removal after session expiry, PDF header geometry, and the existing real-server ledger parity cases. The long-header PDF was rendered and inspected visually.
