# Save, sync and invoice fixes — 24 October 2026

1. Accepted large notes no longer cause sync/audit 413 errors. The 128 KiB
   target isolates a larger record on its own page, including packed startup,
   initial keyset rows and ordered deltas. No note is truncated. The existing
   1 MiB whole-write limit remains; the client checks it before queueing.
   A delta failure after a committed command stays pending reconciliation,
   retaining the original operation ID. Pre-fix sync-page 413 entries retry
   safely without duplicating financial effects.
2. Sync Codes uses the authenticated online maintenance API with the workspace
   epoch, outside the financial outbox. It reconciles the replication cursor
   afterward. Unsupported legacy Sync Codes queue entries are removed; valid
   queued financial actions retain their original IDs. A maintenance failure
   leaves no blocking queue entry. This is tested in both device vaults and
   online outboxes.
3. The separate Python/WSGI app accepts empty CONTENT_LENGTH on bodyless DELETE
   requests. Seven delete endpoints were checked against disposable SQLite;
   linked-history and stock safeguards remain active. This source correction
   is in the parent project's app.py, not the Worker deployment.
4. Invoice edits persist invoice_no within the guarded atomic version update.
   Duplicate numbers are rejected in the client/server and by the database;
   a stale edit cannot change the number or financial data. Blank edited
   numbers retain the existing number. Numbers allow one line, up to 100
   characters, including Bengali and punctuation.
5. Quick search uses the real invoice number and invoice UUID, once per invoice,
   and opens that invoice. The legacy single-sale search remains compatible.
6. With Returns checks actual returned quantities/journal entries. Zero-price
   returns qualify; cancelling a sale without a return does not qualify.
7. Manual Share fallback opens the memo dialog and presents a labelled,
   read-only, selectable textarea. Clipboard permission denial reaches the
   same fallback. Real desktop/mobile browser checks confirm visibility,
   selection, and fit at 390px width. Business text stays escaped.
8. A wrong encrypted-restore password produces a clear translated message,
   including AES-GCM failures with an empty browser error message. Failed
   restore does not replace the existing device records.

Regression evidence: 18 Node test modules, 18 Python/WSGI tests, targeted
queue/replay/large-note tests and real Chrome UI tests. Browser tests use
isolated fixture data and a temporary profile; login/security and HTTP/D1
contracts use a separate freshly built Worker. Native share-sheet behavior is
unchanged. No business reset, live financial write or APK build is part of this
change. External alerts remain disabled.
